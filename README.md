# Интерьер Проект — статический сайт

Независимая версия для `TeaProphet/interior-project-static`. Каталог, фотографии,
контакты и реквизиты редактируются в `/admin` и сохраняются напрямую в GitHub.
Strapi, база данных и сервер авторизации не нужны. Отзывы и заявки удалены.

## Локальный запуск

Node.js 22 или новее:

```sh
npm ci
npm run dev
npm run test:editor
npm run build
npm run preview
```

Открыть `/interior-project-static/`, редактор — `/interior-project-static/admin/`.
Для локальной проверки в рабочем окружении могли использоваться зависимости
исходного проекта через junction; на другом компьютере выполните `npm ci`.

## Публикация

Создать **публичный пустой** репозиторий `TeaProphet/interior-project-static`.
Отправить содержимое этой папки отдельным репозиторием, без истории исходного:

```sh
git init -b main
git add .
git commit -m "Static site with GitHub content editor"
git remote add origin https://github.com/TeaProphet/interior-project-static.git
git push -u origin main
```

Если Git уже инициализирован, пропустить init и remote add.
Settings → Pages → Source: GitHub Actions. Запустить workflow Publish static site.
Адрес: https://teaprophet.github.io/interior-project-static/ . Текущий домен не меняется.
Если репозиторий переименован, обновить `vite.config.ts`, `src/admin/github.ts` и URL в метаданных.
Применимость GitHub Pages к постоянному коммерческому размещению определяется
условиями GitHub; публичность репозитория не отменяет ограничений сервиса.

## Редактирование

Создать fine-grained token в GitHub Settings → Developer settings → Personal access
tokens. Выбрать только этот репозиторий, Contents: Read and write и срок действия.
Вставить в `/admin`. Токен остаётся только в памяти вкладки: после перезагрузки
нужен повторный ввод. Не добавлять его в код, URL, Issues или файлы проекта.
Права распространяются на содержимое репозитория, а не только папку content.

Редактор изменяет `content/furniture/*.json`, `content/contacts.json`, `public/media`.
Первое изображение — обложка; кнопки Раньше/Позже меняют порядок.
JPEG/PNG/WebP — максимум 10 МиБ. Удалённые фото очищаются, только если не используются
другими категориями. Git сохраняет их историю, поэтому не загружайте секретные материалы.

Сохранение — единый коммит. GitHub Actions затем отдельно собирает и публикует сайт.
Сообщение «сохранено» не означает, что сборка завершена: проверьте ссылку Actions.
При конфликте правки остаются в памяти. «Скачать свои правки» сохраняет JSON и новые
изображения в base64 для ручного восстановления; автоматического импорта этого файла нет.
Сначала скачайте правки, затем перезагрузите данные и повторите нужные изменения.

Для отката используйте `git revert <commit>` и push. При ошибке сборки новая версия
не публикуется. Прямые ссылки генерируются для всех существующих категорий.
Копирование index.html обеспечивает работу SPA, но не полноценный HTML-пререндеринг
контента для поисковых роботов.

## Импорт и проверки

Импортированы только опубликованные данные локальной CMS: 11 категорий и 156 фото,
пропусков нет (`IMPORT-REPORT.json`). Исходные 933 файла uploads целиком не копируются.
База, секреты и пользователи CMS отсутствуют в новой версии.
`scripts/import-local.cjs` — одноразовый инструмент миграции из соседнего исходного
проекта; повторно не запускать поверх готового сайта: он восстанавливает исходный frontend.

Тесты проверяют атомарный коммит, конфликт, неверный токен, отсутствие прав,
сетевой сбой и выход. Сборка проверяет категории и существование медиа и создаёт
миниатюры. Онлайн-проверка сохранения требует созданного репозитория и вашего токена.
